# 流光 iOS：产品与架构需求（MVP）

## 1. 产品目标

流光 iOS 是抖音内容采集流水线的轻量客户端。用户从抖音复制分享内容，或在快捷指令中调用“提交到流光”，任务在远程节点继续执行，完成后写入该用户自己的飞书多维表格。

产品不得依赖开发者的 Mac、飞书应用、模型账号或多维表格。每位用户自行提供任务节点及第三方服务凭证，费用和数据归属用户本人。

## 2. 为什么采用远程任务节点

iOS 的后台下载可以由系统进程继续执行，但下载之后的音频处理、多个 API 调用、轮询和飞书写入不能获得持续、确定的后台执行时间。快捷指令和 App Intent 适合做入口，不是常驻任务服务器。

因此 MVP 采用：

```text
抖音分享内容
    ↓
App / 快捷指令（只负责提交）
    ↓ HTTPS
用户配置的流光任务节点
    ↓
解析 → 媒体准备 → ASR → 校对 → 分析 → 飞书
    ↓
iOS 查询状态并展示结果
```

提交成功后用户可以立即锁屏或退出 App。任务节点必须是持续在线的 HTTPS 服务。

## 3. 用户隔离

第一版支持“每个用户一套任务节点”。任务节点中保存该用户自己的：

- 飞书 App ID、App Secret、Base App Token 和数据表；
- 火山语音、阿里百炼、OpenRouter 等第三方凭证；
- 字段映射和处理开关。

iOS 只保存任务节点 URL 和访问令牌。访问令牌存入 Keychain，不写入 UserDefaults、日志或 Git。该设计能保证朋友的凭证不经过开发者的服务器。

以后若开发共享 SaaS 节点，必须另做租户系统、服务端加密密钥库、审计、限流、删除机制和隐私协议，不能直接复用单用户节点。

## 4. MVP 用户流程

### 4.1 首次配置

1. 输入任务节点 HTTPS 地址；
2. 输入该节点生成的访问令牌；
3. 点击“测试连接”；
4. 测试通过后进入首页；
5. 飞书和模型凭证在用户自己的节点配置页面填写。

### 4.2 提交任务

支持以下输入：

- 完整抖音分享文案；
- `v.douyin.com` 短链接；
- 抖音标准作品链接。

App 从混合文本中提取 URL，但将原始分享文本一并提交，避免丢失标题和话题信息。

### 4.3 快捷指令

安装 App 后提供“提交到流光”动作：

- 接收文本参数；
- 调用任务节点创建任务；
- 返回“已提交”和任务编号；
- 不等待转写与分析完成；
- 不要求打开主 App。

用户可在系统快捷指令中接收共享表单输入，并调用该动作。

### 4.4 任务列表

显示：等待、解析中、下载中、转写中、校对中、分析中、写入飞书、成功、可重试失败、永久失败。支持下拉刷新、查看错误和重新提交。

## 5. 安全要求

- 任务节点必须使用 HTTPS；开发调试时才允许 `localhost`。
- 节点访问令牌存储于 iOS Keychain。
- 请求使用 `Authorization: Bearer <token>`。
- 日志不得输出令牌、飞书 App Secret 或模型 API Key。
- 服务端必须进行请求长度限制、频率限制和恒定时间令牌比较。
- App 删除配置时同时删除 Keychain 数据和本地任务索引。
- App Store 版本不得包含任何开发者的真实凭证。

## 6. MVP 边界

第一版包含：SwiftUI 客户端、配置、Keychain、连接测试、提交、任务列表、任务详情、重试、App Intent/快捷指令。

第一版不包含：iPhone 本地 FFmpeg、手机常驻轮询、共享多租户云服务、开发者代管用户密钥、App Store 支付。

## 7. 交付阶段

1. iOS 工程骨架和任务节点 API 契约；
2. 现有 Node 服务实现带鉴权的 `/v1` 接口；
3. 在测试节点完成端到端联调；
4. 增加系统分享扩展和完成通知；
5. TestFlight 内测；
6. 根据内测结果决定是否建设共享云节点。

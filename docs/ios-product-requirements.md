# 流光移动端：产品与架构需求（MVP）

## 1. 产品目标

流光移动端让用户在 iPhone 或 Android 手机上直接处理抖音分享内容，并把作品信息和逐字稿保存到用户自己的飞书多维表格。

产品不依赖开发者的 Mac、飞书应用、语音账号或多维表格。每位用户自行提供飞书与火山引擎凭证，数据归属、服务额度和费用也由用户本人管理。

## 2. 当前架构

iOS 与 Android 采用相同的端内直连架构：

```text
抖音分享内容
    ↓
流光 App
    ↓
解析作品 → 下载临时媒体 → 提取音频 → 火山语音转写
    ↓
用户自己的飞书多维表格
```

处理期间 App 需要保持在前台。系统可能在锁屏、切换应用或内存紧张时暂停或终止任务，因此 MVP 不承诺后台持续处理。

仓库中的 Node.js 服务仍保留网页工作台、后台监听和可选 Worker API。它适合需要长时间后台运行、模型降级、内容分析和任务重试的用户，但不是移动端首次使用的必需组件。

## 3. 用户配置与隔离

首次配置需要：

- 飞书自建应用 App ID 与 App Secret；
- 目标飞书多维表格的完整 Base 链接；
- 火山引擎豆包语音“快捷 API 接入”页面生成的 API Key。

iOS 使用 Keychain 保存 App Secret 与语音 API Key；Android 使用 Android Keystore 生成的 AES-GCM 密钥加密整套配置。敏感值不得写入日志、Git、云备份或安装包。

每台设备只访问用户明确配置的飞书和语音服务。若未来建设共享 SaaS，必须另行设计租户隔离、服务端密钥库、审计、限流、删除机制和隐私协议。

## 4. MVP 用户流程

### 4.1 首次配置

1. 阅读用户自有服务说明；
2. 填写飞书 App ID 与 App Secret；
3. 粘贴飞书 Base 完整链接；
4. 填写火山语音 API Key；
5. 保存到设备安全存储并进入工作台。

### 4.2 采集

支持完整抖音分享文案、`v.douyin.com` 短链接和抖音标准作品链接。App 从混合文本中跳过非抖音链接，保留原始分享内容，并按以下阶段处理：

1. 解析作品元数据和媒体候选；
2. 在飞书创建初始记录；
3. 下载临时视频并提取 16 kHz 单声道 WAV；
4. 调用火山语音生成逐字稿；
5. 更新飞书状态、逐字稿和来源；
6. 失败时把错误原因写回对应记录。

### 4.3 采集库

采集库直接读取目标飞书数据表，展示记录状态、标题、封面、分享内容和业务字段。进入采集库时刷新，停留期间定时更新，也允许用户手动刷新。

### 4.4 快捷工具

- 保存无水印视频：解析可用播放流并保存到系统相册；
- 提取逐字稿：只执行转写，并保存到飞书“逐字稿库”；
- 提词器：编辑文稿、保存本地草稿，支持倒计时、速度、字号、镜像和循环播放。

### 4.5 系统入口

- iOS 提供“提交到流光”App Intent，可由快捷指令调用；
- Android 接收系统 `ACTION_SEND` 文本分享，回填采集页并等待用户确认。

## 5. 安全要求

- 业务请求只允许 HTTPS；
- 飞书链接必须属于 `feishu.cn`、`larksuite.com` 或其真实子域名；
- 抖音输入只接受 `douyin.com`、`iesdouyin.com` 或其真实子域名；
- 敏感输入不得进入系统 SavedState、日志、截图、测试产物或仓库；
- App 禁止备份包含凭证的本地配置；
- 清除配置时同时删除安全存储中的密钥与本地配置；
- 安装包不得包含开发者或测试账号的真实凭证。

## 6. MVP 边界

当前包含：四步配置、端内采集、采集库、无水印视频保存、逐字稿库、提词器、系统分享入口和分项设置。

当前不包含：可靠后台续跑、持久任务队列、自动重试、通知、跨设备同步、离线媒体处理、多租户云服务、App Store 或应用商店支付。

需要后台稳定处理、模型降级、内容分析、任务租约和重试时，应使用仓库中的 Node.js 服务。

## 7. 验收要求

- Android：`testDebugUnitTest`、`assembleDebug`、`lintDebug` 通过；
- iOS：Xcode 单元测试通过；
- Node.js：`npm run check` 与 `npm test` 通过；
- 模拟器验证首次配置、主导航、系统分享回填和三项快捷工具入口；
- 正式发布前使用用户自己的测试账号完成一次真实抖音、火山语音和飞书端到端验收。

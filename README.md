# 流光：抖音内容采集到飞书

流光是一套在本机运行的内容采集工具。粘贴抖音分享文案或链接后，它会自动获取作品信息、生成逐字稿、整理内容重点，并把结果保存到飞书多维表格。

你不需要手动下载视频、复制标题或整理逐字稿；管理页面会持续显示每条任务进行到哪一步，以及失败后是否正在重试。

## 适合谁

- 需要批量整理短视频选题和素材的内容运营人员
- 希望把视频转成可搜索文字资料的个人创作者
- 使用飞书管理内容库，但不想手工维护大量字段的团队
- 希望在自己的电脑上保存配置，而不是把飞书和模型密钥交给第三方平台的用户

项目目前是本地工具，不是在线 SaaS。运行期间电脑需要保持开机并联网。

## 你可以完成什么

1. 在网页中粘贴抖音分享文案或链接。
2. 自动识别作品并获取标题、作者、发布时间、时长、互动数据和话题。
3. 提取音频并生成逐字稿；质量异常时自动切换备用模型。
4. 从逐字稿提取开头钩子、主题和核心知识点。
5. 在页面查看处理进度、错误原因、逐字稿和分析结果。
6. 将任务、结果、封面和可选的视频附件保存到飞书。
7. 修正配置或网络问题后，在页面重新处理失败任务。

同一个作品会按作品 ID 去重，避免重复写入。

## 最终会保存哪些内容

| 内容 | 示例 |
| --- | --- |
| 作品信息 | 标题、作者、作品 ID、发布时间、视频时长、分辨率 |
| 互动数据 | 点赞、评论、收藏、分享数量 |
| 内容资料 | 话题、封面、视频逐字稿 |
| 内容分析 | 开头钩子、钩子类型、主题、核心知识点 |
| 任务状态 | 当前阶段、尝试次数、下次重试时间、失败原因 |

## 开始使用

### 1. 准备账号和环境

你需要：

- Node.js 18 或更高版本
- 一个已发布的飞书自建应用，并开通多维表格和云盘相关权限
- 至少一个语音识别服务；首次使用推荐配置 OpenRouter

项目依赖已经包含 FFmpeg，不需要单独安装。

### 2. 安装项目

```bash
git clone https://github.com/zhanglongfeng27101797/douyin-feishu-collector.git
cd douyin-feishu-collector
npm install
```

如果你使用的是其他 fork，请把克隆地址替换为对应仓库地址。

### 3. 首次配置

先启动管理页面：

```bash
npm run web
```

浏览器打开 [http://127.0.0.1:3210](http://127.0.0.1:3210)，点击右上角“设置”，填写：

- 飞书 App ID 和 App Secret
- 已有多维表格的 App Token；如果还没有，可以留空
- OpenRouter API Key 和模型名称
- 是否需要在飞书保存视频

没有现成表格时，点击“保存并准备飞书表格”。系统会创建多维表格、数据表和所需字段，并把生成的配置保存在本机 `.env.local`。

配置完成后按 `Ctrl + C` 停止仅页面模式，再启动完整服务：

```bash
npm start
```

以后通常只需要运行 `npm start`。

### 4. 创建任务

打开管理页面，把抖音“分享 → 复制链接”得到的整段文字粘贴到输入框，点击“创建任务”。

页面关闭后，只要 `npm start` 进程仍在运行，后台任务就会继续处理。重新打开页面可以继续查看进度。

## 已有飞书表格和旧配置

旧的配置方式继续可用：

```bash
cp .env.example .env.local
```

填写已有的 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_APP_TOKEN` 和模型服务配置后，运行：

```bash
npm run setup:fields
npm start
```

使用多个飞书账号时，可以分别准备环境文件：

```bash
ENV_FILE=.env.company.local npm start
```

完整配置项及兼容规则见[技术设计文档](docs/technical-design.md#配置系统)。

## 视频保存方式

默认不会把完整视频写入飞书，只会在临时目录中提取低码率音频用于转写，处理结束后自动删除。

| 页面选项 | 适用情况 | 空间占用 |
| --- | --- | --- |
| 不保存视频 | 只需要元数据、逐字稿和分析结果 | 最低，推荐默认使用 |
| 保存压缩视频 | 需要在飞书中回看内容 | 中等，默认压缩为 720p |
| 保存原视频 | 必须保留原始文件 | 最高，兼容旧版本 |

视频保存方式不会改变转写音频质量。

## 数据保存在哪里

- 任务和内容结果：飞书多维表格
- 封面及可选视频：飞书云盘附件
- 飞书与模型配置：项目目录中的 `.env.local`
- 下载和转写中的媒体：操作系统临时目录，任务结束后删除

项目不使用独立数据库，页面也不会把任务数据保存在浏览器里。`.env.local` 已被 Git 忽略，页面读取配置时不会把已有密钥返回给浏览器。

## 常用命令

| 命令 | 用途 |
| --- | --- |
| `npm start` | 同时启动管理页面和飞书监听器 |
| `npm run web` | 只启动管理页面，用于首次配置或查看数据 |
| `npm run collect -- "分享文案或链接"` | 直接处理一条内容 |
| `npm run watch` | 只启动飞书监听器 |
| `npm run setup:fields` | 为已有表格补齐字段 |
| `npm run parse -- "分享文案或链接"` | 只测试链接识别，不写入飞书 |

## 常见问题

### 页面显示“处理中”很久，是不是卡住了？

语音转写和内容分析由后台完成，长视频或模型繁忙时会等待较久。页面会显示当前阶段；出现明确错误时可以修正配置后点击重试。关闭浏览器不会中断仍在运行的后台进程。

### 为什么飞书里没有完整视频？

默认设置就是不保存视频，以减少飞书空间和上传时间。需要回看时，可以在页面设置中选择“保存压缩视频”。

### 模型提示所在地区不可用怎么办？

在页面设置或 `.env.local` 中更换 OpenRouter 模型。系统支持主模型和备用模型链，不需要修改业务代码。

### 必须新建飞书表格吗？

不需要。填写已有表格的 App Token 后，运行字段初始化即可继续使用；也可以让页面自动创建新表格。

### 配置保存后为什么监听器没有立即变化？

部分并发数和运行策略会在进程启动时读取。保存设置后重启 `npm start`，即可确保全部配置生效。

## 使用限制

- 抖音页面和接口可能变化，解析能力需要随平台更新。
- 视频播放地址可能过期，系统会自动换源并尝试重新解析，但不能保证所有作品都可读取。
- 云端模型会产生调用费用，请在对应服务商后台设置预算或额度提醒。
- 请只处理你有权使用的内容，并遵守平台规则和相关法律。

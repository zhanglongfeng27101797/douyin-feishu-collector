# 流光

> 把抖音分享链接变成可检索、可复用的飞书内容资料。

流光运行在自己的电脑上。粘贴一段抖音分享文案后，它会自动获取作品信息、生成逐字稿、提炼内容重点，并把任务过程和最终结果保存到飞书多维表格。

适合需要持续整理短视频素材的内容运营、创作者和小团队。项目不是在线 SaaS：密钥保存在本机，业务数据留在飞书，运行期间电脑需要保持开机联网。

## 手机客户端

仓库已包含 Android 与 iOS 客户端源码。两端使用相同的产品结构和用户自有服务配置：凭证安全保存在设备本机，解析、下载、转写和飞书归档由 App 直接完成，长视频处理期间需要保持 App 在前台。

### Android

Android 版使用 Kotlin 与 Jetpack Compose，并以 iOS 版为交互基准，包含四步首次配置、抖音分享采集、飞书采集库、无水印视频保存、逐字稿提取、提词器、系统分享入口和安全设置。

- Android 工程与运行说明：[`android/README.md`](android/README.md)

### iOS

仓库已包含用户自带飞书与火山语音凭证的 iOS 客户端。iPhone 直接解析作品、准备音频、完成转写并写入飞书，并提供系统快捷指令入口。

- iOS 工程与运行说明：[`ios/README.md`](ios/README.md)
- iOS 产品和架构需求：[`docs/ios-product-requirements.md`](docs/ios-product-requirements.md)

## 从链接到内容资料

```mermaid
flowchart LR
  A["粘贴分享内容"] --> B["解析作品信息"]
  B --> C["语音转写"]
  C --> D["提炼内容重点"]
  D --> E["归档到飞书"]
```

每条任务会得到作品元数据、互动数据、话题、封面、视频逐字稿，以及开头钩子、主题和核心知识点。页面会展示当前处理阶段、失败原因和重试状态，同一作品按作品 ID 自动去重。

默认不保存完整视频，只临时提取低码率音频用于转写。需要回看时，可以选择把 720p 压缩视频或原视频作为附件写入飞书。

## 开始使用

准备 Node.js 18+、一个已发布并拥有多维表格权限的飞书自建应用，以及至少一个语音识别服务。首次使用推荐 OpenRouter；项目依赖已包含 FFmpeg。

安装项目：

```bash
git clone https://github.com/zhanglongfeng27101797/douyin-feishu-collector.git
cd douyin-feishu-collector
npm install
```

第一次运行时先打开配置页面：

```bash
npm run web
```

访问 [http://127.0.0.1:3210](http://127.0.0.1:3210)，在右上角“设置”中填写飞书 App ID、App Secret 和模型服务密钥。

- 已有飞书表格：填写链接中的 App Token。
- 没有飞书表格：App Token 留空，点击“保存并准备飞书表格”。

配置会写入被 Git 忽略的 `.env.local`。完成后按 `Ctrl + C` 停止仅页面模式，再启动完整服务：

```bash
npm start
```

以后只需运行 `npm start`，浏览器仍然访问同一个地址。

## 日常使用

在页面输入框粘贴抖音“分享 → 复制链接”得到的整段文字，点击“创建任务”。任务会在后台继续执行，关闭页面不会中断仍在运行的服务。

如果某个模型在当前地区不可用，可以在设置中更换模型；转写结果过短或异常重复时，系统会自动尝试备用模型。网络或媒体地址暂时失效时，任务会换源或进入延迟重试，修正问题后也可以手动重新排队。

部分并发和运行策略在进程启动时读取。修改配置后重启 `npm start`，可以确保全部设置生效。

## 数据与空间

飞书多维表格是业务数据主存储，项目不额外挂载数据库。封面和可选视频使用飞书附件；下载中的媒体位于操作系统临时目录，任务结束后清理；页面只在浏览器保存主题偏好，不保存任务数据。

视频归档有三种选择：

- `none`：不保存视频，空间占用最低，也是默认值。
- `feishu_compressed`：保存 720p 压缩视频，适合日常回看。
- `feishu`：保留原视频，用于兼容已有部署，空间占用最高。

云端转写和内容分析可能产生费用，请在服务商后台设置预算或额度提醒。
